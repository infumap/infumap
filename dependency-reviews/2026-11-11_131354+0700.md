## attohttpc 0.30.1 — blocking Windows socket ownership defect

**Inspected behavior.** Both manifests; library/request builder, settings,
session, proxy, body and send loop; `streams.rs`, `happy.rs`; TLS selection and
all three TLS implementations; response/buffer/chunk/decompression/text modules;
multipart wrappers and lazy writer; error/charset modules. Enabled features are
rustls with webpki roots and JSON, without native TLS, multipart or compression.
HTTP connects to caller URLs, configured proxy endpoints and bounded redirects;
DNS racing creates per-address connection threads. File-body/multipart reads
are caller-selected. TLS validation defaults on; bypasses require explicit
danger APIs. Debug logs include request URLs/queries and proxy URLs: do not
assume credential-bearing query strings are redacted when debug logging is enabled.

**Blocking evidence and trigger.** In `src/streams.rs:134` (`connect_tcp`), the
Windows branch at 145 copies `stream.as_raw_socket()` into the timeout closure.
At 149–168 a normal total-request deadline can expire; the thread drops its
receiver and calls `closesocket(socket)`. At 176 the same original `TcpStream`
is returned to `BaseStream`, still owned and used by the request/response. No
ownership transfer, replacement, duplicate socket or close-once coordination
removes that owner's subsequent access or destructor.

Rust's installed source confirms the later close in
`library/std/src/os/windows/io/socket.rs:194` (`OwnedSocket::drop`, calling
`closesocket` at 198), under
`/home/lima/.rustup/toolchains/1.99-aarch64-unknown-linux-gnu/lib/rustlib/src/rust/`.
The [published Rust source](https://doc.rust-lang.org/src/std/os/windows/io/socket.rs.html#194-200)
has the same destructor.
[Microsoft's closesocket contract](https://learn.microsoft.com/en-us/windows/win32/api/winsock/nf-winsock-closesocket#remarks)
explicitly permits immediate descriptor reuse and prohibits concurrent closes
with other Winsock calls. These external sources were read only to resolve the
concrete platform ownership question, not as substitutes for crate inspection.

Consequently, an ordinary slow request on Windows, with a total timeout and
concurrent socket creation, can close connection A in the timeout worker, allow
its raw value to be reused by B, then perform a read/write/close through A's stale
owner against B. Unrelated connection disruption is a concrete safe-to-run
concern; unexpected I/O on B is also possible depending on scheduling. No
malicious response or adversarial parser input is required. Exact interleavings
and an exploit were not tested. The Unix branch uses a cloned stream and
`shutdown` instead; this specific finding is Windows-only, with
`single-threaded` disabled. `aws-creds/src/credentials.rs:246,277` defaults its
credential HTTP requests to a **30-second total timeout**, so the trigger is
present in the graph on Windows, not merely a dormant public option.

**Additional nonblocking observation.** `src/request/mod.rs:203–279` follows
redirects with the same headers, body and method, updating Host but not clearing
Authorization/Cookie or forbidding HTTPS-to-HTTP downgrade. A hostile redirect
can therefore disclose supplied credentials. This requires an untrusted or
compromised response and is recorded separately under this workflow's
operator-vetted-input scope. `aws-creds` disables redirects for container tokens
at `credentials.rs:434`; its IMDS token requests still use default redirects.
There is no claim that this observation is fixed or harmless in a deployment
that accepts hostile responses. `ProxySettings::for_url` also matches
`no_proxy` by bare hostname suffix (101–118), without a domain-label boundary.

**Decision/remaining work.** Full source review completed with a blocking
finding. Not certified; record a `safe-to-run` violation for **`=0.30.1` only**
in Infumap's store. No publisher decision, workaround, dependency change or
upstream notification was made. Resolution requires a separate ownership-safe
implementation/release and review of the chosen artifact. Previous independent
reviews of aws-creds/rust-s3 do not certify their attohttpc dependency.

## sysinfo 0.37.2

**Evidence/behavior.** Both manifests, platform/feature routing in `src/lib.rs`,
common System/Process refresh and signal boundaries; Linux system/process/file
helpers, CPU/disk/component/network/product query paths; native query, resource
cleanup, process, registry, WMI, interface and disk-control entry points across
Windows, Apple and FreeBSD; Unix user/group and interface helpers. Optional
C interface, serde, parallel and unsupported-platform routes were examined for
their dispatch and effects, without proving all FFI buffer invariants.

`rust-s3/src/bucket.rs:2103` creates an empty System then refreshes only memory,
using available memory to select upload concurrency. Linux
`src/unix/linux/system.rs:233` reads `/proc/meminfo`; Windows
`src/windows/system.rs:163` uses GlobalMemoryStatusEx/K32GetPerformanceInfo;
Apple `src/unix/apple/system.rs:155` uses sysctl/host_statistics64; FreeBSD
`src/unix/freebsd/system.rs:94,500` uses kernel statistics and kvm (initialized
with `/dev/null` for the memory file). These are expected host-memory queries.

Broader APIs intentionally expose process command lines/environments, user and
hardware metadata, registry OS information and local interfaces. They do not
upload those results. Windows WMI connects to local `root\\WMI`, querying
MSAcpi_ThermalZoneTemperature (`windows/component.rs:215,255`); storage ioctls
query seek penalty/performance (`windows/disk.rs:379,412`); Apple SMC requests
READ_KEYINFO/READ_BYTES (`unix/apple/macos/component/x86.rs:231,261`).
Windows `taskkill.exe /PID <numeric pid> /F` is confined to explicit
`Process::kill_with` (`windows/process.rs:365`); Unix uses explicit signals.
Apple's `sysctl` command is in an upstream test, not library refresh.

**Effects/limits.** Linux `remaining_files` (`unix/linux/system.rs:54`) raises
this process's soft RLIMIT_NOFILE to its existing hard limit on first use and
budgets half for cached proc files. It is called by process-file caching or the
explicit open-file-limit API, not S3's memory refresh. Windows load-average
queries install periodic five-second performance sampling; component queries
initialize process COM security. These implement the requested query facilities,
do not install persistent software or modify arbitrary files, and are not
unexpected harmful behavior under this criterion. Reading process environments
is inherently sensitive; acceptance assumes the operator intentionally requests
such APIs. No arbitrary credential-file collection or unexplained destination
was found. Native dependencies retain separate vet gaps; neither all FFI
soundness nor all host-dependent failure modes were proved. Upstream tests
launch child processes and use named local fixtures, including `test.txt`;
they were not run. No safe-to-deploy claim.

**Decision.** No concerning changes found within the reviewed scope; certified
safe-to-run as a full exact-version AI source review, with these effects noted.

## async-compression 0.4.52

**Evidence/behavior.** Both manifests; `src/lib.rs`, `macros.rs`, generic
bufread/write decoder/encoder state machines and buffer writer; Tokio and
Futures adapters and generating macros, including unsafe ReadBuf initialization
handoff. Enabled features: `brotli,gzip,tokio,zlib`. `tower-http`'s runtime
compression/decompression body modules use `tokio::bufread` adapters.

The crate transforms bytes through caller-supplied readers/writers and selected
compression-codecs, forwards flush/close/backpressure, and bounds its default
write buffer to 8192 bytes. Constructors expose explicit quality, dictionaries,
memory limits and optional codec parallelism. It does not choose files, network
destinations or child processes. Native codec/build behavior belongs to separate
dependencies; compression-core 0.4.34 and compression-codecs 0.4.47 are still
separate uncovered targets, not certified by this record. Highly expanding
streams and caller-supplied custom codecs require their own resource policy.

**Nonblocking observation.** `src/generic/write/buf_writer.rs:114–116` takes a
small input with sufficient spare capacity but calls
`self.buf[self.buffered..].copy_from_slice(buf)` without limiting the destination
to buf.len(). If invoked with input shorter than the remaining buffer, this
panics. The defect is in a private helper. Follow-up caller tracing shows public
codec write state machines use `poll_partial_flush_buf`, rather than this
helper's `poll_write`; a public trigger was **not established**. The initial chat
description of a write-path issue must be read with this narrower reachability
limit. Infumap's bufread path does not use it. No fix, test, or exploit claim.
This dormant correctness defect does not establish a safe-to-run violation.

**Decision.** Certified safe-to-run, full exact-version AI source review, with
the nonblocking private-helper defect and separate codec coverage limits noted.

## heifer 0.4.0

**Evidence/behavior.** Both manifests and library modules `lib`, `reader`,
`sequence`, `image`, `color`, `depth`, `metadata`, `iptc`, `uncompressed`, `icc`,
`hdr`/`hdr/iso21496`; optional encoding and image-crate integration routes and
their resource/I/O effects. No features are enabled for this dependency in
Infumap: the default encoder and image integration are disabled.

`src/lib.rs::{decode_srgb_rgba8,decode_item_with,decode_hvc1,decode_grid}`
parses caller-supplied bytes, invokes heifer-isobmff/heifer-hevc-dec, assembles
image items and alpha, applies crop/rotation/mirroring and converts color to sRGB.
Metadata/ICC/IPTC/HDR handling parses embedded bytes and transforms arrays; XMP
is data, with no URL fetching or external entity processing. `reader::Loaded`
only reads/seeks its supplied reader, checks extents against its length, limits
metadata boxes to 64 MiB and top-level scanning to 4096 boxes. It opens no paths.
Decoder recursion is bounded to depth four, default image size to 2^28 pixels,
and tile workers to available CPUs and tile count. Infumap additionally sets
`max_threads: 1` (`infumap/src/util/image.rs:70`) under its image-processing permit.
The pixel limit is not a small aggregate-memory bound: frames, metadata, tiles
and color conversion can coexist, and metadata/reader extents are not all
bounded by the pixel cap. This is not an adversarial-image resource-hardening
certification.

Optional encoding builds an in-memory HeifWriter, bounded tile workers and a
finite quality search; optional image hooks register only on an explicit API
call and read/write caller streams. Examples read caller files and write chosen
output paths; they do not run during consumer compilation. No hidden filesystem,
network, execution, installation or unrelated computation path was found.

**Limits/decision.** Certified safe-to-run for this exact crate's full AI source
review. This does **not** certify heifer-hevc-dec 0.4.0 or heifer-isobmff 0.4.0;
their substantial implementations remain separate vet gaps. Existing cached
RUSTSEC-2026-0456/0458/0460 entries concern those helpers and specify patched
versions >=0.3.27; reading these entries was not a fresh advisory scan or a
regression proof. No exhaustive decoder, arithmetic, color-correctness or
malicious-image audit was performed.
