## Memory safety finding in both Rand releases

With `serde` (0.9.5) or `serde1` (0.8.8), `UniformChar` deserializes the integer sampler before checking its wrapped upper endpoint. `UniformInt::max` uses wrapping subtraction and addition. The check can accept a sampler whose range crosses the integer boundary, and it fails to exclude the zero-range sentinel, which `UniformInt::sample` interprets as the full integer domain. The validated upper endpoint therefore fails to bound the values actually sampled. `UniformChar::sample` restores the surrogate offset and calls `core::char::from_u32_unchecked`, whose precondition can be violated. This is a source-level memory-safety defect when a consumer deserializes untrusted sampler state and samples it. Concrete effects beyond undefined behavior were not investigated.

Infumap's all-feature, all-target resolved graph enables neither affected deserializer. The finding concerns production input handling and does not establish a `safe-to-run` violation in the reviewed graph. Both delta certifications are withheld. No violation entry was added. The release changelogs describe a fix for invalid serialized samplers, but the source still lacks validation of the full sampler range. Resolving the finding requires checking the sampler's actual domain before accepting deserialized state.

## Rand 0.9.2 → 0.9.5

Used by `rav1e` and `tantivy-columnar`. Google covers 0.8.5, with ISRG deltas to 0.9.1 and 0.9.2. Both manifests, README and changelog reflect removal of the optional logging dependency and narrower docs.rs features. `src/lib.rs` removes logging macros. `src/rngs/reseeding.rs::reseed_and_generate` panics on periodic reseed failure, preventing continued generation from the old state at the cost of availability if the reseeder fails. Explicit reseeding still returns the error. The OS RNG selection and dependency requirements are unchanged. `src/seq/slice.rs` changes a Miri test annotation.

`src/distr/uniform_int.rs::UniformInt::max` and `src/distr/uniform_other.rs::deser_sampler` implement the incomplete check described above. The standalone lockfile drops `log` and updates existing RNG, platform, serialization and development dependency resolutions, including `rand_core` and `getrandom`. The crate has no build script. Decision covers the delta only. Certification withheld.

## miniz_oxide 0.8.9 → 0.9.1

`flate2` 1.1.11 uses the Rust backend through image codecs and HTTP compression dependencies. Bytecode Alliance covers the base via 0.7.1 → 0.8.0 → 0.8.5 → 0.8.9. Both manifests raise optional `simd-adler32` from 0.3.3 to 0.3.8 and permit alloc-only Serde, forwarding std when requested. Infumap enables SIMD and allocation and resolves `simd-adler32` 0.3.10 and `adler2` 2.0.1. Serde is inactive. The packaged lock also updates Rust std workspace and Serde dependencies. `src/lib.rs` preserves the unsafe-code prohibition and extends no_std to Serde builds. `src/serde/big_array.rs` switches imports to core.

`src/deflate/{buffer,core,mod,stored,stream,zlib}.rs` add cloneable state, allocate a fixed-size LZ code buffer on wasm32, adjust strategy/window selection and headers, add flush modes, and skip hash-chain maintenance for stored blocks. Buffer sizes stay bounded by existing constants. The compressed distance table indexes groups of four distances with the same extra-bit count. Flush changes write local format markers, preserve pending bits and retain finish padding and checksum emission. The compressor's new low-level options have correctness caveats: zero window bits lose the zlib wrapper selection, and the raw/RLE flag conjunction in `window_bits_from_flags` tests disjoint masks. These concern caller-selected parameters and level transitions. Infumap's flate2 path uses the existing compressor constructor.

`src/inflate/{core,mod,output_buffer,stream}.rs` tighten Huffman table checks and add bounded writes through `decompress_with_limit`. The existing entry point uses the slice's full capacity. I traced the literal, stored-block and back-reference paths through the output cap and checked match copy bounds. The slow match path compares an absolute end position with remaining bytes, so some matches take the bounded transfer path unnecessarily. This is an efficiency issue with a bounded copy and no demonstrated security impact. The rest of the changes here are documentation, diagnostics and enum extensibility. No build script, process execution, external I/O or unsafe code was introduced. This is a delta-only AI source review. No concerning changes found within the reviewed security scope. The delta qualifies for `safe-to-run`.

## Rand 0.8.5 → 0.8.8

Used by Infumap directly and by `twox-hash`. Google covers the base. Both manifests, README and changelog document removal of optional logging and experimental packed SIMD. The manifests add `serde_json` for development only. The standalone lock drops `log` and `packed_simd_2` and updates RNG, platform and serialization resolutions. The artifact has no build script.

In `src/distributions/`, `float.rs`, `integer.rs`, `mod.rs`, `uniform.rs` and `utils.rs` remove SIMD sampling and its unsafe intrinsic and pointer operations. Scalar support remains. `utils.rs` restricts no-std float helpers, and `distribution.rs` activates nightly `TrustedLen` for an iterator whose `next` always produces an item and whose size hint is `(usize::MAX, None)`. `other.rs` and `weighted_index.rs` update docs cfgs. `uniform.rs::deser_sampler` and `UniformInt::max` have the shared validation defect described above. `src/rngs/adapter/reseeding.rs::reseed_and_generate` now panics on failed periodic or post-fork reseeding. `src/lib.rs` removes logging and enables the nightly trait. `src/rng.rs`, `src/rngs/{mod,small,std,thread}.rs` and `src/seq/{index,mod}.rs` mainly update docs cfgs, explicit iterator lifetimes and Miri handling. Decision covers the delta only. Certification withheld.
