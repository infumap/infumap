### htmlescape 0.3.1

**Evidence.** Published Cargo.toml (no Cargo.toml.orig is packaged); all production src/{lib,encode,decode,io_support,entities}.rs, package inventory, README, benchmark entry and .travis.yml. The 252 named entity rows were structurally verified as literal name/Unicode-character pairs, with the five minimal entity strings read directly.

**Behavior and security reasoning.** The encoder traverses caller text, replacing HTML delimiters or attribute punctuation with entities. The decoder consumes caller UTF-8 through a small entity-state machine, resolves literal tables/numeric character values, and writes to the supplied Write object; convenience helpers use local Vec/Cursor storage. io_support implements UTF-8 conversion and interrupted-read retries without selecting any file or endpoint. There is no build script, dependency proc-macro, unsafe block, environment discovery, credential access or autonomous process/network action. Tantivy 0.27.0 src/snippet/mod.rs:152-167 calls encode_minimal for snippet text, adding its own configured highlight tags. No crate features or runtime dependencies are declared.

**Nonblocking findings.** Nonblocking observations: encode.rs:132-139::write_hex uses write for the three-byte entity prefix and ignores a successful short byte count before write_all of the suffix. A caller writer accepting fewer than three bytes can therefore receive malformed entity output without an error; Vec-backed encode_attribute and Tantivy encode_minimal do not use that failing path. This is output correctness, not an established injection or machine-effect exploit. The packaged .travis.yml:9-10 also pipes an HTTP artifact-uploader download into sh using a CI token in the query. Executing that legacy upstream CI step could run unauthenticated remote code and expose that CI token in transit. It is not a Cargo build/test hook or invoked by Infumap; it was not executed and its remote payload was not fetched. This dormant CI exposure does not establish a safe-to-run violation in the reviewed consumer build.

**Scope and limits.** Full exact-version AI source review. No exhaustive HTML-context/XSS, entity conformance, custom I/O or integer-capacity proof. encode_minimal is for HTML text, not arbitrary unquoted attribute insertion. Unterminated entity buffering and returned strings follow caller input size. Upstream CI deployment is outside this consumer certification; it should not be reused as trusted automation. No builds or tests were run.

**Decision and records.** No concerning changes found within the reviewed scope; certified safe-to-run. Record only this exact version in `infumap/supply-chain/audits.toml`, with AI identity, date, report reference and these limitations. No target remains incomplete.

### sketches-ddsketch 0.4.2

**Evidence.** Both manifests and all production src/{lib,config,store,ddsketch,encoding}.rs, including the complete public Java-compatible encoder/decoder before its inline tests. Also inspected package inventory, standalone dev lockfile sources, Makefile and release workflow. Config/Store/DDSketch derive routing and serde fields were read, not executed.

**Behavior and security reasoning.** Config maps floating-point values to logarithmic bin indices. DDSketch maintains positive/negative dense stores plus zero count and summary statistics, merges compatible sketches and estimates quantiles. Store grows/collapses owned Vec<u64> bins; defaults allow 2048 bins per sign. Java encoding writes only a Vec, and decoding consumes a caller byte slice through checked byte fetches and bounded-length varint operations, populating local stores. Every bin decode iteration consumes input or returns an error; there is no synthetic spin based solely on an encoded bin count. Tantivy 0.27.0 src/aggregation/metric/percentiles.rs:143-249 constructs default sketches, adds values, merges/queries them and exposes Java-format output. Active features serde/use_serde serialize the owned state through the caller. No unsafe/FFI, build script, filesystem/env/credential access, endpoint, process, installation or background work.

**Nonblocking findings.** Nonblocking input-validation observation: the public Java decoder accepts signed indices narrowed to i32 (encoding.rs:277-317::decode_store), then Store computes i32 range spans and offsets with unchecked arithmetic (store.rs:72-106,159-162). Extreme or inconsistent crafted bin ranges can overflow these calculations and panic under overflow checking or later invalid indexing. Serde also derives Deserialize directly for internal store/config fields without a validation step, so deserialized state is not guaranteed to obey constructor invariants. This is hostile-input availability/invariant-hardening evidence; no end-to-end Infumap exploit was established or run. The inspected Tantivy wrapper emits Java bytes and uses default constructors, though its serde-derived intermediate collector can deserialize sketch state. No unexpected sensitive/unrelated machine effect was established under operator-vetted inputs.

**Scope and limits.** Full exact-version AI source review. No statistical error-bound, complete numerical-overflow, malformed serialization or aggregate-memory proof. Bin limits do not bound number of application sketches, total update count or externally deserialized Vec sizes. Independent Serde behavior and application transport/admission policy remain separate. No builds or tests were run.

**Decision and records.** No concerning changes found within the reviewed scope; certified safe-to-run. Record only this exact version in `infumap/supply-chain/audits.toml`, with AI identity, date, report reference and these limitations. No target remains incomplete.
