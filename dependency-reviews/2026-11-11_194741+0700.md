### infer 0.19.0

**Evidence and behavior.** Both manifests, complete production `src/{lib,map}.rs` and all ten matcher modules (app/archive/audio/book/doc/font/image/mod/odf/text/video; mod is routing/support). Static matcher functions compare signatures, bounded header fields, ZIP entry names, text prefixes and image/container brands against supplied bytes. They identify executable/script/certificate magic as data without executing it. Custom matchers are explicit caller function pointers. `lib.rs:240-250::get_from_path` opens only its argument, obtains its metadata and reads at most 8192 bytes. `doc.rs:106-123::ole2` opens cfb::CompoundFile on an in-memory Cursor and checks root CLSID; it does not extract embedded files or touch host paths. Cfb 0.7.3 has its own existing local review, which was verified in the previous report and is not replaced here. No writes, environment lookup, network, process, unsafe code or build hook.

Infumap directly calls `infer::get(data)` in `src/util/mime.rs:32,46`, not the path helper. Active features default/std/alloc/cfb. No-std OLE fallback and alloc/custom dispatch branches were inspected. The example reads the command-line-selected file and prints its inferred type, without installation or execution of that file.

**Nonblocking recursion observation.** `src/matchers/archive.rs:233-261::is_zst` and `268-296::is_lz4` recursively skip a frame using the untrusted frame length. Each recursive step consumes at least eight bytes, but there is no recursion-depth bound. A large chain of zero-length skippable frames can therefore cause deep call stacks and possible stack exhaustion in builds without tail-call elimination (Rust does not guarantee it). The 8192-byte path helper limits that entry point's input, whereas Infumap's byte-slice API has no such intrinsic cap in this module. This is a source-derived hostile-input availability concern; stack exhaustion through the complete application was not reproduced. No credential access, exfiltration or unrelated modification is established, so it is nonblocking under this criterion.

**Scope and limits.** No comprehensive signature accuracy, container parser, integer-overflow or hostile-file proof. Direct byte-slice calls are bounded only by caller input; nested CFB parsing and caller matchers have their own resource/effect contracts. No builds or tests were run.

**Decision.** No concerning changes found within the reviewed scope; certified safe-to-run, with the nonblocking observation retained. Full exact-version AI source review, recorded only in Infumap's audit store; dependency versions remain unchanged.

### lru 0.18.5

Concurrent Cell mutation can cause a data race/undefined behavior through safe caller APIs. This is a source-derived unsound bound, not an executed reproducer or an established Infumap exploit. The inspected Tantivy consumer does not transfer these iterators and uses usize/Block under its mutex. No path from this defect to the criterion's unexpected harmful machine effects was established. It is retained as nonblocking under the workflow's memory-safety boundary; no safe-to-deploy claim or fix.

**Scope and limits.** No exhaustive aliasing, panic-safety, raw-node invariant or concurrency proof. Only the shared Iter Send defect above is asserted; the separate IterMut Send implementation is not classified by analogy. No builds or tests were run.
