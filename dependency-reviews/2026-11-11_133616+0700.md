## redox_syscall 0.5.18

**Evidence and behavior.** Both manifests; `src/lib.rs`, `call.rs`, all four
`arch/{aarch64,riscv64,x86,x86_64}.rs` syscall stubs; `io/{io,mmio,pio}.rs`;
ABI data/error/number definitions, directory buffers and signal helpers;
`scheme/{mod,scheme,scheme_mut,scheme_block,scheme_block_mut,seek}.rs`,
`schemev2.rs`, and the developer generator. Scheme variants were compared to
their shared implementation. `call.rs` forwards explicit file paths, handles,
buffers, mapping requests, namespace requests and futex operations to Redox
system calls. Architecture assembly performs the expected syscall instruction;
PIO/MMIO operates on explicitly supplied hardware ports/memory. Nothing
automatically opens a path, sends data, changes permissions or installs handlers.

Both graphs require it through `parking_lot_core 0.9.12`, whose manifest selects
it only for `target_os = "redox"`. Its `src/thread_parker/redox.rs` uses only
the futex wait/wake interface and TimeSpec. These are expected synchronization
effects. This is a Redox ABI crate; the architecture cfg alone is not a claim
that its syscall wrappers can be meaningfully called on Linux/Windows.

**Nonblocking observations.** `src/sigabi.rs:72–88`,
`Sigcontrol::set_allowset`, loads both words but writes both updates to
`self.word[0]` at lines 82–83. The second update should address the other word
to implement the represented 64-signal allowset. Direct use can therefore leave
upper-half masks stale and corrupt the lower-half mask; a caller relying on it
could mishandle signal delivery. `src/dirent.rs:89–109`, `DirentIter::next`,
does not reject `record_len` shorter than header plus NUL before slicing and
can panic on malformed directory records. If the record is longer than the
remaining buffer it returns `Some(Err(Invalid))` without advancing, so a caller
that continues after errors can loop indefinitely. These are source defects,
not reproduced results. Neither helper is used by parking_lot_core's Redox
parker. No path to the prohibited machine effects was established; inactive
helper correctness/parser defects do not block this safe-to-run review. They
remain unfixed and are not covered by a safe-to-deploy claim.

**Decision and limits.** Full exact-version AI source review supports
safe-to-run certification in **both stores** (recorded), with those observations retained.
Raw scheme packets and native memory/port interfaces rely on their intended
kernel/driver contracts; this is not an unsafe-API soundness or signal-memory
ordering proof. No Redox kernel or hardware execution was performed.

These are compression settings, not hidden execution or unrelated computation.
No independent filesystem target, environment/credential lookup, network
destination, process execution or payload download was found. Native backend
implementation/build behavior remains each dependency's separate obligation.

**Decision and limits.** No concerning changes found within the reviewed scope;
certified safe-to-run, full exact-version AI source review.
Uninitialized-buffer handoffs trust dependency progress counts. Caller output
space bounds each call, not total decompressed size or aggregate codec memory;

**Decision and limits.** No concerning changes found within the reviewed scope;
certified safe-to-run, full exact-version AI source review.
TIFF reads the supplied remainder into memory; PNG/WebP metadata and HEIF boxes
can also require large reads. HEIF's 65535-byte Exif check occurs after reading
an extent, not before all possible allocations. These are resource-hardening
