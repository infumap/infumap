## pxfm 0.1.30

**Evidence and behavior.** Both manifests, `src/lib.rs` and module routing;
`bits.rs`, `common.rs`, `shared_eval.rs`, polynomial and double/triple/dyadic
number helpers; power/log/exp and trigonometric argument-reduction paths;
cube-root FMA dispatch; gamma iteration and hypot correction loops; Bessel/error
function table/dispatch structures. Relevant locations include
`pow.rs::f_powi/f_powi_hard/f_pow`, `powf.rs:802-841::f_powf/dirty_powf`,
`cube_roots/cbrtf.rs:80-152`, `sin_cosf/argument_reduction.rs:353-392`,
`gamma/gamma_p.rs:84-145`, and `triangle/hypot.rs:41-186`.

Required by moxcms's gamma, RGB and color-space calculations. The crate has no
runtime dependencies and takes/returns numerical values; there is no raw-pointer
memory interface, native extern call, allocation-driven worker, filesystem,
credential, network, environment or process path. Unsafe operations are
unchecked numeric conversions and CPU-specialized function calls. OnceLock
initializers choose local compiled implementations after AVX/FMA detection;
they do not launch a task. Power's integer fallback shifts its exponent to
zero; gamma/beta convergence loops use fixed iteration caps; hypot corrections
operate on scalar residuals. Coefficient bits feed floating-point evaluation,
not executable-memory conversion. The actual println calls are in cfg(test)
modules (`pow_exec.rs:755-771`, `bessel/j0f.rs:408-425`); other generator output
snippets are comments.

**Decision and limits.** No concerning changes found within the reviewed scope;
certified safe-to-run for this full exact-version AI source review. Numerical
accuracy, every conversion precondition and every correction-loop invariant
were not proven; this acceptance does not assert arbitrary-input correctness.

## objc2-io-kit 0.3.2

**Evidence and behavior.** Both manifests, `translation-config.toml`, complete
handwritten `src/{lib,macros,consumes_argument}.rs`, generated module/feature
routing, extern/declaration/ABI-encoding structures across every generated file,
and executable wrapper bodies. A structural pass located **356 generated
function bodies**: each declares one native function then forwards caller
arguments, with boolean conversion, nullable-return checks and/or CFRetained
ownership conversion. The body forms were inspected; no extra operation or
fixed destination occurs in them. USB interfaces are C vtable layouts with
caller-invoked function pointers, rather than startup code. Local macros only
compute bitfields/error constants. The generated cf_type macro's dependency
implementation was inspected as context: reference conversions and delegated
CF equality/hash/debug behavior, without an autonomous initializer.

`src/generated/mod.rs:20` links only Apple's **IOKit** framework. Declarations
expose powerful intended APIs: registry/device matching, property reads/writes,
HID event injection, notification registration, power management, mapping and
caller-selected URL resource I/O. For example, `mod.rs:12306-12362` forwards its
supplied CFURL and buffers directly; it contains no hardcoded endpoint or file
selection. `consumes_argument.rs::consume` relinquishes an explicit matching
dictionary reference before the three native service calls. No calls happen
merely because the crate is imported.

Dependency path: Infumap → rust-s3 0.38.0 → sysinfo 0.37.2 → this crate, selected
only on macOS/iOS by sysinfo. Sysinfo disables this crate's default features,
enabling std/libc and hidsystem through component support. Its Apple code uses
registry/device information for CPU/disk/components/product data and explicitly
releases handles. Hardware serial/UUID retrieval is an exposed sysinfo operation,
not covert collection by these bindings. Rust-s3's actual caller,
`bucket.rs:2102-2111::calculate_max_concurrent_chunks`, refreshes available memory
to choose upload concurrency; it does not request product serial/UUID data.

**Decision and limits.** No concerning changes found within the reviewed scope;

`hll/hash_set.rs:60-163`, `hll/array{4,6,8}.rs` payload readers,
`codec/{decode,encode}.rs`, `req/compactor.rs:223-270`,
`tdigest/sketch.rs:641-705`, `thetafamily/tuple/sketch.rs:640-742`, and
`thetafamily/tuple/policy.rs`.

Tantivy 0.27.0 explicitly enables **hll** for cardinality aggregations
(`aggregation/metric/cardinality/`). HllSketch hashes supplied values into
coupons and promotes small lists/sets to register arrays. Its public precision
range is 4..21; union merges/downsamples supplied sketches. Codec I/O is a
Cursor over supplied bytes and a returned Vec, not a filesystem or network
stream. HLL readers validate family/version/precision/mode and payload sizes;
set probes detect a full traversal. Optional families similarly maintain
caller-selected summaries in owned collections. Large CPC compression and HLL
interpolation tables are data; Theta's unrolled packing is integer/slice code.
Generic hashing, ordering, summary policies and custom serialization invoke
explicit caller implementations. Optional REQ uses rand::random<bool> for its
compaction coin; entropy access belongs to its declared rand dependency and
implements the stochastic algorithm. REQ/rand is inactive in this consumer
resolution; the crate has no active runtime dependency for hll.

There is no unsafe code, FFI, build hook, hidden initializer, file selection,
credential lookup, outbound endpoint, subprocess or background worker in the
reviewed package. Memory use follows selected precision/configuration and
supplied values. Limits on one sketch do not bound total aggregate memory.

**Decision and limits.** No concerning changes found within the reviewed scope;

## moxcms 0.8.1

**Evidence and behavior.** Both manifests, `src/lib.rs`; profile/header/tag/string,
TRC and LUT reading/writing; defaults/date and color-space/gamma helpers;
transform creation, layouts and channel checks; scalar and SSE/AVX/AVX512/NEON
selection and buffer effects; interpolation/prepared LUTs, optional Katana
multi-ink stages, extended-range/in-place routes and CMYKA interception.
Key locations: `profile.rs:978-1176`, `reader.rs:344-550,559-678,713-803`,
`writer.rs::encode/write_mluc`, `transform.rs::create_transform_nbit`,
`conversions/rgbxyz.rs:599-625`, `conversions/rgb_xyz_factory.rs:443-500`,
`conversions/{avx,sse,neon}/rgb_xyz.rs`, `conversions/avx/interpolator.rs:249-277`,
`conversions/lut_transforms.rs`, `conversions/katana/md_pipeline.rs`, and
`nd_array.rs::Hypercube`.

Image 0.25.10 requires it for local color-profile/transfer conversions; moxcms
uses num-traits and the separately reviewed pxfm. Default features enable LUTs
and SIMD conversion paths. Public transforms take supplied pixel slices and
profiles and return/write converted pixels. Header parsing uses an in-memory
Cursor. Default parsing caps profile size below 10 MiB and TRC entries at 40,000;
LUT paths check table sizes and checked dimension/offset products. MAB/MBA
currently applies a separate hardcoded 10,000,000-value CLUT cap. try_vec uses
fallible reserve where selected. These controls do not cap all aggregate scratch
or resampled LUT memory.

SIMD implementations access prepared lookup tables, supplied pixel chunks and
aligned local scratch arrays. They do not map host files, access executable
memory or perform native OS calls. Factory feature/CPU checks select compiled
implementations; interpolation fetches use computed color-grid offsets. Optional
stages build buffers proportional to pixels/inks and call explicit stage
implementations. The only production host query found is SystemTime::now for
profile timestamps. Source file reads occur in cfg(test) profile fixtures;
README file-opening examples are documentation. No production environment,
credential, network, process, installation or unrelated-file mutation path was
found. Writer returns profile bytes in a Vec.

**Nonblocking observations (source-derived, not executed).**

1. `dat.rs:78-81,102-107`: Default calls now; on a non-wasm clock before
   UNIX_EPOCH, now's error branch calls Default again, recursively. Constructors
   using default profile timestamps and encode can therefore exhaust the stack
   or fail to return on that misconfigured clock. This is an availability defect
   tied to an anomalous host clock, not evidence of hidden computation or a
   criterion violation in ordinary post-epoch operation. The acceptance assumes
   the operator's clock is at/after the epoch. No comprehensive date-range proof.
2. `writer.rs:133-150::write_mluc` uses UTF-8 byte length × 2 for record sizes and
   offsets, then emits UTF-16 units. For `é`, it advertises four bytes while
   emitting two. Non-ASCII profile text can therefore have incorrect lengths,
   displaced following records or rejected/corrupt metadata. The returned output
   buffer is affected; no unrelated file is written. Image's inspected CICP
   conversion path does not call this profile writer. This is a nonblocking
   serialization correctness defect, not a safe-to-deploy certification.

Neither observation was fixed or disproved. There is no confirmed cargo-vet
criterion violation to record. Neither warrants withholding an otherwise
completed safe-to-run review under the documented scope.

**Decision and limits.** No concerning changes found within the reviewed scope;
certified safe-to-run for this full exact-version AI source review, with those
nonblocking observations. This does not prove every SIMD load/index or parser
invariant sound, make memory use universally bounded, or establish numerical
color correctness. Native/SIMD paths were read, not executed.
