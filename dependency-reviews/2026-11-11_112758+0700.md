## rpassword 7.5.4

**Evidence/behavior.** Both manifests; all seven modules
`src/{lib,config,feedback,utf8,unix,windows,wasm}.rs`; examples, integration source,
`.cargo/config.toml`, `.envrc`, `shell.nix`, `githooks/*` and packaged CI.
`lib.rs:81` reads characters and applies editing/feedback, `:258/265/270` exposes
the configured/default entry points, and `config.rs:125` defaults to hidden input
and the platform console. Unix `RawModeInput` (`unix.rs:62/129/47`) opens
`/dev/tty` or caller paths, changes termios and restores saved modes on Drop;

restores console modes and closes handles. WASM uses input/output streams without
terminal configuration. Optional partial password display requires explicit
configuration. No networking or background key capture was found.

**Limitation.** Unix Ctrl-C raises SIGINT before `RawModeInput` is dropped
(`lib.rs:129`, `unix.rs:162`), so default signal termination can bypass mode
restoration; a surrounding shell may restore the terminal. This was not executed
or reproduced and is an abort/terminal-state limitation, not evidence of hidden
persistent reconfiguration. No complete secret-memory-erasure or FFI-soundness
claim is made. Packaged Nix shell setup intentionally changes developer toolchains
and Git hooks if entered; neither it nor package-local target runners/hooks is
invoked by Infumap's consumer build. No build script.

**Consumer/scope/decision.** CLI login/rekey intentionally call default
`read_password`/`prompt_password`. Full version review; no base needed.
No concerning behavior found within the reviewed scope; certified safe-to-run
with the terminal-restoration limitation recorded in persistent notes.
