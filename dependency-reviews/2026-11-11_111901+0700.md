## synstructure 0.13.2 → 0.14.0

**Evidence and changes.** Read all six changed files: both manifests, README,
`src/lib.rs`, packaged lockfile and VCS metadata. The source changes in
`src/lib.rs:255` (`merge_generics`), `:434` (`get_ty_params`), and `:1722`
(`add_trait_bounds`) turn duplicate-parameter checks into match guards, replace a
boolean-fill loop with `fill(true)`, and initialize the new Syn AST attribute
fields with empty vectors. Both manifests switch Syn 2 to Syn 3 and declare Rust
1.71; feature forwarding remains the same. The packaged lock changes Syn,
proc-macro2, quote and unicode-ident resolutions, and VCS metadata names the new
release commit. That standalone lock does not resolve Infumap's consumer build.

**Reasoning and graph.** These operations inspect caller-supplied syntax and emit
trait bounds/implementation tokens. Surrounding visitors, generic merging and
`gen_impl_parse` show no added machine I/O, hidden execution or unrelated work.
The library has no build script; the unchanged macro definitions remain covered
by the accepted base. Infumap uses it through `yoke-derive` and `zerofrom-derive`,
including the ICU4X/URL graph, with `default` and `proc-macro` enabled. The actual
consumer resolution uses Syn 3.0.9; it is a separate dependency with existing vet
evidence, not independently audited in this delta.

**Scope and decision.** Delta only. Accepted base: Google's full 0.13.1 audit by
Manish Goregaokar plus Mozilla's 0.13.1 → 0.13.2 delta by Nika Layzell.
No concerning changes found within the reviewed scope; certified safe-to-run
for this exact delta in the Infumap audit store. No dependency or
compatibility policy was changed.

## const-random-macro 0.1.16

**Evidence and behavior.** Full source review of `src/lib.rs:1–57` and
`src/span.rs:1–104`, both manifests and VCS metadata; the remaining packaged files
are MIT/Apache license text. There is no build script, binary, native payload or
packaged lockfile. `const_random` accepts integer types or a literal byte-array
length and emits numeric literal/cast/array tokens. `get_seed` caches 32 bytes of
OS entropy through getrandom unless `option_env!("CONST_RANDOM_SEED")` captured
an operator-provided seed when the macro crate was compiled. `hash_stuff` feeds
that seed and the invocation span's debug string into SHAKE256. Integer results
use fixed-size outputs; arrays allocate and emit the explicitly requested length.

**Reasoning and graph.** Entropy reads and the single named compile-time seed
are expected for build-time random constants. The span is hashed, not used to
open a source file. There is no environment enumeration, credential-file access,
network transmission, process launch or runtime initialization emitted here.
Malformed types/lengths or unavailable entropy can fail compilation; unusually
large arrays consume resources proportional to the source request. This is not
an independent cryptographic assessment or recursive review of tiny-keccak,
once_cell or getrandom. Their versions/features were identified in the consumer
graph. The getrandom entry point and host entropy backend were consulted as
context, not certified as a new target.

Infumap's path is `config → rust-ini → ordered-multimap → dlv-list → const-random
→ const-random-macro`. `dlv-list` currently has `std` enabled; its const-random
invocation in `src/lib.rs:2254` is in the non-std alternative. That limits current
use but is not the basis for accepting the fully inspected macro. The companion
README documents randomness and deterministic seed selection.

**Scope and decision.** Full review of this exact macro version, with no base
required. No concerning changes found within the reviewed scope; certified safe-to-run
in the Infumap audit store. Companion/dependency gaps
are not certified by this record.
